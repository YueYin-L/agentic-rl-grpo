# 中文简历项目材料

## 推荐标题

科研检索工具路由策略优化｜Agentic RL 原型

## 项目介绍

参考 Microsoft Agent Lightning 的 rollout–reward–resource 分层思路，独立实现 CPU
可运行的科研工具路由优化原型；将中文科研查询建模为上下文状态，在 4 类本地工具间执行有界决策，
记录结构化轨迹并依据任务成功、Schema 合法性和调用成本计算奖励。使用 LinUCB
上下文赌博机更新轻量路由策略，不涉及 LLM 权重训练。

## 技术栈

Python、LinUCB、FastAPI、Pydantic、Pytest、Ruff、MyPy、uv、JSONL

## 主要工作

- 构建 `Task → Action → Observation → Reward` 的单步 Agent 环境，封装物种信息查询、
  论文检索、证据比较和摘要总结 4 类确定性工具；记录动作、工具输出、延迟、奖励与终止原因，
  解决工具路由过程不可追踪的问题。
- 设计工具选择、执行成功、输出 Schema 和调用成本组成的透明奖励函数，并使用 48 条训练任务、
  24 条模板与主题均隔离的验证任务建立可复现评测流程。
- 实现 LinUCB 上下文赌博机策略并与固定关键词路由基线对比；在合成验证集上，工具选择准确率由
  50.0% 提升至 87.5%，平均奖励由 0.40 提升至 0.85。结果、逐条轨迹和 3 个失败样本均保存于
  `reports/`，未将该结果外推为真实线上效果。
- 提供 FastAPI `/route` 与 `/health` 接口、策略 JSON 持久化及离线流水线；8 个测试通过，
  Ruff 与 MyPy 检查通过，并以真实 HTTP 请求完成接口验收。

## 30 秒介绍

我做的是一个 Agentic RL 的最小工程闭环，不是大模型微调。系统把科研查询编码成上下文特征，
在 4 个工具之间选择动作，执行后根据工具是否正确、输出是否合法和调用成本返回奖励，再由
LinUCB 更新路由策略。验证集使用训练中未出现的模板和物种，准确率从关键词基线的 50% 提升到
87.5%。我同时保留了完整轨迹和失败分析，其中剩余错误主要来自否定表达，说明当前关键词特征
无法表示语序和否定关系。

## 高频追问

### 这是 PPO 或 GRPO 吗？

不是。当前优化的是轻量工具路由策略，算法是 LinUCB 上下文赌博机，没有更新 LLM 权重。
我选择它是为了先用 CPU 完成可解释、可复现的状态—动作—奖励闭环；模型权重 RL 是后续阶段。

### 为什么准确率能从 50% 提升到 87.5%？

关键词基线按固定优先级匹配，第一个命中的词会覆盖后续真实意图；LinUCB 能同时利用物种、论文、
比较、摘要、多文档和证据等特征，并根据任务奖励学习各工具对应的特征权重。这个数字只针对
24 条合成隔离验证任务，不代表真实用户流量。

### 剩余失败是什么？

3 个失败样本都包含“不要总结，搜索……”这类否定表达。状态编码只统计关键词，因此看到“总结”
后仍可能选择摘要工具。下一步应加入否定和语序特征，或使用文本编码器，但必须冻结新的测试集，
不能继续用当前验证集调参。

## 不能写入简历

- 基于 Agent Lightning 训练或微调了大模型；
- 使用 PPO、GRPO、DPO 或 VERL 完成策略训练；
- 真实科研检索准确率达到 87.5%；
- 实现多步自主规划、多智能体协作或完整 RAG；
- 达到生产级性能或完成线上部署。
